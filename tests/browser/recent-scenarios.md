# Recent downloads — Chrome scenarios

Use session-local Node 24.20.0/npm 11.19.0. Choose two free owned ports, then start `PORT=<api-port> WEB_PORT=<web-port> PREVIEW_CONTROL=/tmp/musiclatte-recent-control node --import tsx tests/support/recent-preview.ts`. Start Vite with `MUSICLATTE_PREVIEW_API_TARGET=http://127.0.0.1:<api-port> npm run dev:web -- --host 127.0.0.1 --port <web-port>`. Stop only the processes started for this preview.

Normal entry: `/music`, synthetic login from `tests/support/auth-harness.ts`, then **Recent downloads**. The product has no preview route or control variable. API, playlist and media credentials are never read from the browser or logged. The harness is test-only and excluded from production builds/contexts.

`PREVIEW_CONTROL` is a local file containing one mode; it never reaches product HTML or source. `new` creates a later synthetic snapshot; cursors pin their snapshot/range. Custom range filters the synthetic ledger. API trace may contain `/recent-downloads`, selected media and playlist requests; no full library/folder/tag scan is required for recent reads. Real worker/import/iPhone validation belongs to Phase 3 Step 14.

The harness also exposes `/__preview/mobile` and `/__preview/narrow` on the owned API port. They frame the same normal web route at 390×844 and 320×844; they do not provide an alternate product route or mock component tree.
