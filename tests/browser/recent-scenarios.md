# Recent downloads — Chrome scenarios

Use session-local Node 24.20.0/npm 11.19.0. Start `PREVIEW_CONTROL=/tmp/musiclatte-recent-control node --import tsx tests/support/recent-preview.ts` (3000), then `npm run dev:web -- --host 127.0.0.1` (5173). Check ports first; stop only the processes started for this preview.

Normal entry: `/music`, synthetic login from `tests/support/auth-harness.ts`, then **Recent downloads**. The product has no preview route or control variable. API, playlist and media credentials are never read from the browser or logged. The harness is test-only and excluded from production builds/contexts.

| Scenario         | Control / actions                                                                       | Expected                                                                                                                                         |
| ---------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Default          | `normal`; Music → Recent downloads                                                      | Exact server 7×24-hour filter and asOf, no UI query params, heading focus                                                                        |
| Pages            | Select songs → select page → load more → select page → load final page                  | 39 ready checkboxes across 41 events; registering/missing have explanation/recovery only; no duplicated event rows                               |
| Final focus      | Keyboard/pointer Load more while selected at 390/320                                    | Focus remains on Load more and its hit target is visible above selection bar/player/nav                                                          |
| Partial add      | `partial`; select 39 songs → existing playlist                                          | 16 applied, 16 failed, 7 unattempted; 23 remain selected; failure occurs before second BFF write                                                 |
| Partial retry    | Change to `normal`; Retry remaining songs                                               | Real P2 receipts/batching; playlist grows from 3 to 42, applied songs are not added twice                                                        |
| Uncertain writes | Existing P2 mutation tests                                                              | Unknown upstream write outcome remains fenced; do not turn it into an automatic duplicate write                                                  |
| New item         | Select a song; `new`; wait for visible-page probe or focus window; Show new downloads   | Banner leaves current snapshot intact; refreshed first page preserves selected IDs, no automatic selection of the new song                       |
| Player           | Play loaded songs; pause; select a row, change locale/range, refresh/error and navigate | P1 player and ordered queue survive; selection does not play a song; long valid IDs stream                                                       |
| Dates            | Custom dates; reversed/empty values then valid dates; Last 7 days                       | Invalid field focused, linked error; inclusive local days → UTC exclusive end; successful period change resets selection; server range displayed |
| States           | `loading`, `empty`, `error`/`503` then normal + retry                                   | Scoped state; retained list/selection/player on refresh 503; empty recovery to Music                                                             |
| Access           | `denied`, `unsupported`, `unavailable`; reload or refocus to restore capabilities       | Music entry absent, direct route recovery; unavailable current page retains snapshot/selection                                                   |
| Auth             | `401`; refresh; then normal and login                                                   | Login with canonical `/music/recent` returnTo                                                                                                    |
| Visual           | KO/EN; 1800×863, 390×844, 320×844, actual Chrome 200% zoom, reduced motion              | No horizontal scroll/clipping, named controls, last row/action reachable, keyboard overlay Escape/return focus                                   |

`PREVIEW_CONTROL` is a local file containing one mode; it never reaches product HTML or source. `new` creates a later synthetic snapshot; cursors pin their snapshot/range. Custom range filters the synthetic ledger. API trace may contain `/recent-downloads`, selected media and playlist requests; no full library/folder/tag scan is required for recent reads. Real worker/import/iPhone validation belongs to Phase 3 Step 14.
